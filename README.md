# Тренажёр оператора ДДС

Тренажёр предназначен для обучения операторов системы-112 и диспетчеров дежурно-диспетчерских служб. Обучающийся принимает учебный звонок от виртуального заявителя, выясняет характер происшествия, адрес и сведения о пострадавших. Преподаватель определяет условия разговора и назначает задание группе.

Речь распознаётся и обрабатывается на сервере организации. Заявитель отвечает по сведениям, записанным в сценарии. Оператор может перебивать его и уточнять ответы. Реплики сохраняются в истории попытки.

Программа работает в браузере. Устанавливать приложение на рабочие места не требуется. Для работы используются три роли:

| Роль | Доступные действия |
|---|---|
| Администратор | Создание пользователей, назначение ролей, блокирование доступа |
| Преподаватель | Создание и редактирование сценариев, их утверждение и перенос, формирование групп, назначение и завершение занятий, просмотр состояния участников |
| Обучающийся | Работа со списком происшествий, создание карточки, приём и завершение учебного звонка |

Сценарии разных преподавателей разделены. Сценарий нельзя изменить во время активного занятия. После редактирования его необходимо снова утвердить.

## Требования

### Оборудование и программное обеспечение

| Параметр | Сервер | Рабочее место |
|---|---|---|
| Процессор | Intel Core i7 / Xeon или аналог, от 6 ядер | Intel Core i5 или аналог |
| Оперативная память | От 32 ГБ | От 16 ГБ |
| Накопитель | NVMe SSD от 512 ГБ | SSD от 256 ГБ |
| Архитектура серверного комплекта | x86-64 | Определяется ОС и браузером |
| Сеть | Постоянный IPv4-адрес в локальной сети | Gigabit Ethernet |
| Звуковое оборудование | Не требуется | Гарнитура с микрофоном |

На сервере необходимы Docker Engine с Docker Compose, Python 3 и OpenSSL. Установка выполняется администратором операционной системы. На рабочих местах используются актуальные версии Chrome, Firefox или Яндекс.Браузера под Windows 10/11 либо Ubuntu 20.04 и выше.

Обработка речи выполняется на CPU. Выделенный графический ускоритель не требуется. Сервер рассчитан на 20 одновременных разговоров. Число сессий программно не ограничивается и зависит от производительности сервера.

### Подключение рабочих мест

Пользователи открывают адрес вида `https://192.168.1.10`. Вместо адреса из примера используется IP-адрес сервера учебного центра. На экране входа указываются логин, пароль и номер АРМ. Доменное имя и внешние службы выдачи сертификатов не требуются.

Для доступа к микрофону браузер должен доверять сертификату сервера. При первоначальной настройке создаётся локальный центр сертификации. Его сертификат устанавливается на каждое рабочее место по порядку, указанному в п. 3.2.

### Подготовка к работе в изолированной сети

При сборке серверного комплекта загружаются контейнерные образы, зависимости и закреплённые версии речевых моделей. Сборку выполняют до отключения внешней сети. После установки модели находятся в образе речевого сервиса; во время занятий программа не обращается к облачным моделям.

Для переноса в изолированную сеть сохраните собранные образы командой `docker image save` и загрузите их на целевом сервере командой `docker image load`. Перенесите также исходный комплект с файлом `compose.yaml`. На целевом сервере выполните настройку адреса и сертификатов, затем запустите `docker compose up -d --no-build`. Файл `.env` и закрытые ключи создаются для конкретной установки.

## Установка и работа

### Установка сервера

Скопируйте проект в отдельный каталог на сервере. Перейдите в этот каталог и выполните:

```bash
python3 deploy/setup.py
```

Введите постоянный IPv4-адрес сервера. Программа создаст сертификаты в `deploy/tls` и файл `.env`. В файле находятся два параметра:

| Параметр | Назначение |
|---|---|
| `SERVER_IP` | Адрес, по которому пользователи открывают тренажёр |
| `DB_PASSWORD` | Пароль PostgreSQL; создаётся автоматически при первоначальной настройке |

При повторном запуске настройки существующий пароль базы сохраняется. Не меняйте его отдельно от пароля пользователя PostgreSQL.

Соберите и запустите комплекс:

```bash
docker compose up -d --build
```

Первоначальная сборка включает загрузку моделей и занимает больше времени, чем последующие обновления. Дождитесь запуска компонентов:

```bash
docker compose ps
```

Для `db`, `speech`, `backend` и `web` должно отображаться состояние `healthy`; для `worker` — `Up`. В локальную сеть публикуется порт 443. Порты базы данных и речевого сервиса наружу не публикуются.

### Установка сертификата на рабочие места

Передайте на рабочие места файл `deploy/tls/ca.crt`. Закрытый ключ `ca.key` и ключ сервера `server.key` остаются на сервере.

В Windows откройте `ca.crt`, выберите «Установить сертификат», затем хранилище «Доверенные корневые центры сертификации». Для установки на весь компьютер требуются права администратора.

В Ubuntu скопируйте сертификат в системное хранилище:

```bash
sudo cp ca.crt /usr/local/share/ca-certificates/training112.crt
sudo update-ca-certificates
```

Если браузер использует собственное хранилище, импортируйте `ca.crt` в разделе сертификатов центров сертификации его настроек. Перезапустите браузер и откройте `https://IP-АДРЕС-СЕРВЕРА`. Страница должна открываться без предупреждения о сертификате.

Сертификат сервера выдаётся на один год. Для его обновления повторно выполните `python3 deploy/setup.py` и `docker compose up -d --force-recreate web`. Корневой сертификат при этом сохраняется; повторная установка на рабочие места не нужна. При изменении адреса сервера обновите также backend командой `docker compose up -d --force-recreate backend web`.

### Создание администратора

На сервере выполните в интерактивном терминале:

```bash
docker compose exec backend create-admin
```

Программа последовательно запросит логин, пароль и подтверждение пароля. Пароль на экране не отображается. Логин содержит от 3 до 32 латинских букв, цифр или знаков подчёркивания; пароль — от 8 до 128 символов.

После сообщения «Администратор создан» откройте тренажёр и войдите с указанными данными. Другие учётные записи создаются в разделе «Пользователи системы».

### Подготовка пользователей

Войдите как администратор. Создайте отдельную учётную запись преподавателя и учётные записи обучающихся. Укажите для каждой записи логин, пароль и роль.

Для временного прекращения доступа нажмите «Заблокировать» напротив пользователя. Блокирование сохраняет учебную историю. Собственную учётную запись заблокировать нельзя.

### Создание сценария

Войдите как преподаватель и откройте раздел «Сценарии». Нажмите «Создать».

Укажите тип происшествия, адрес, сложность, норматив, источник обращения и имя заявителя. Нажмите «Продолжить»: откроется черновик сценария со сведениями для заявителя и критериями оценки. Проверьте название, сведения и эталонные значения критериев. Инструкция отображается до звонка, поэтому ответы заявителя в ней не указывают.

Нажмите «Сохранить». Сервер проверит диалог и заранее запишет голосовые реплики. Когда появится «Готов к утверждению», просмотрите сведения и нажмите «Утвердить».

Кнопка «Изменить» открывает форму изменения. После сохранения изменённый сценарий необходимо снова утвердить.

Для переноса нажмите «JSON» у сценария. Полученный файл можно загрузить кнопкой «Импорт». Импорт создаёт отдельный сценарий и запускает его проверку.

Неактуальный сценарий убирается кнопкой «Скрыть». Ранее назначенные занятия и их история сохраняются.

### Формирование группы

Откройте раздел «Группы». Укажите название группы и службу или организацию, затем нажмите «Создать группу».

Выберите созданную группу, отметьте обучающихся и нажмите «Добавить выбранных». В списке «Участники» отображается сохранённый состав группы. Если пользователя нет среди доступных, администратор должен создать для него учётную запись обучающегося или разблокировать её.

Группа объединяет получателей одного задания. Для индивидуального занятия создайте группу с одним участником. Изменение состава влияет на следующие запуски занятий; уже выданные задания не отзываются.

### Назначение и проведение занятия

Откройте раздел «Занятия». Выберите группу и утверждённый сценарий. Нажмите «Создать занятие».

Когда участники будут готовы, нажмите «Открыть приём звонков» у созданного занятия. Задания появятся у обучающихся автоматически. Преподаватель видит, кто ещё не приступил, кто выполняет задание и кто закончил разговор. Состояние участников обновляется каждые пять секунд.

Для окончания занятия нажмите «Завершить занятие для всех». Текущие звонки будут остановлены, а новые попытки по этому занятию станут недоступны.

### Выполнение задания обучающимся

Войдите под своей учётной записью и укажите номер рабочего места. Убедитесь, что статус оператора — «Доступен». После запуска занятия преподавателем на экране появится входящий вызов. Нажмите «Принять», подключите гарнитуру и разрешите браузеру доступ к микрофону. После принятия система создаст карточку происшествия и начнёт учебный разговор.

Выслушайте заявителя и задавайте уточняющие вопросы. Во время разговора заполните данные заявителя, тип и обстоятельства происшествия, адрес и сведения о пострадавших. Система предлагает службы по выбранному типу; при необходимости измените список вручную. Завершите разговор кнопкой с телефонной трубкой, проверьте карточку и нажмите «Сохранить». После подтверждения карточка передаётся указанным службам, а оператор возвращается к списку происшествий.

При кратковременном обрыве связи программа восстанавливает тот же разговор. Если восстановить его не удалось, оператор возвращается к списку происшествий; пока занятие открыто, система повторно направит ему учебный звонок.

После сохранения карточки преподаватель видит проверку адреса, имени заявителя, типа происшествия, описания и времени сохранения. Описание сопоставляется с эталоном локальной моделью. Неоднозначный ответ передаётся преподавателю для проверки. Результат и рекомендации доступны обучающемуся через значок подробностей в списке происшествий. Преподаватель записывает экспертную оценку и комментарий в разделе «Результаты».

### Обслуживание и завершение работы

Перед обновлением преподаватели должны завершить занятия. Сохраните резервную копию базы:

```bash
docker compose exec -T db pg_dump -U training112 -d training112 -Fc > training112.dump
```

Храните копию вне каталога проекта. Отдельно сохраните `.env`, каталог `deploy/tls` и том `speech_audio` с подготовленными голосовыми репликами. Резервное копирование базы следует выполнять не реже одного раза в сутки.

Для восстановления базы остановите `web`, `worker`, `backend` и `speech`, оставив PostgreSQL запущенным. Восстановление заменяет содержимое существующей базы:

```bash
docker compose exec -T db pg_restore -U training112 -d training112 --clean --if-exists < training112.dump
docker compose up -d
```

Для обновления замените файлы проекта и выполните `docker compose up -d --build`. Не удаляйте файл настроек, сертификаты и постоянные тома. Изменения структуры базы применяются при запуске backend.

Журналы компонентов доступны командой:

```bash
docker compose logs --tail=100 backend speech worker web
```

Для остановки комплекса выполните `docker compose down`. Команда сохраняет постоянные тома. Выключать сервер следует после завершения занятий.

## Сообщения и действия

| Сообщение или состояние | Порядок действий |
|---|---|
| Ошибка сертификата в браузере | Проверить адрес сервера и установку `ca.crt`; при истечении срока администратор обновляет сертификат |
| Нет открытых заданий | Преподавателю проверить состав группы и открыть приём звонков |
| Сценарий ещё не утверждён | Открыть сценарий, дождаться подготовки и утвердить его |
| Проверка диалога и запись голоса | Дождаться окончания обработки; если состояние не меняется, администратору проверить `worker` |
| Не удалось подготовить | Проверить сведения о происшествии, сохранить сценарий повторно; при повторении ошибки проверить журнал `worker` |
| В группе нет обучающихся | Добавить участников; проверить, что их учётные записи не заблокированы |
| Микрофон недоступен | Подключить гарнитуру и разрешить браузеру доступ к микрофону в браузере и ОС |
| Сервер или соединение перегружены | Повторить попытку после освобождения ресурсов сервера |
| Не удалось восстановить звонок | Вернуться к заданию и начать отдельную попытку |
| Логин уже занят | Указать другой логин при создании пользователя |
| Пароли не совпадают | Повторить интерактивное создание администратора |

## Устройство системы

### Программные компоненты

| Каталог или сервис | Назначение |
|---|---|
| `site`, контейнер `web` | Интерфейс React/TypeScript, захват микрофона и воспроизведение звука; nginx принимает HTTPS |
| `backend` | Java/Vert.x: авторизация, учебные данные и WebSocket-шлюз |
| `speech` | Python/ONNX Runtime: обнаружение речи, распознавание и выбор ответа заявителя |
| `worker` | Проверка сценариев, подготовка аудио и фоновая обработка завершённых попыток |
| `db` | PostgreSQL: пользователи, сценарии, назначения и события занятий |

Веса моделей включены в образ `speech`. Piper создаёт аудиофрагменты при подготовке сценария. Во время разговора воспроизводится готовое аудио; при отсутствии фрагмента разговор завершается с ошибкой. Подмена модели или переход на другой сервер не выполняются.

Backend и Speech работают на одном хосте и используют общий сетевой namespace контейнера. Внутренний ZeroMQ endpoint — `tcp://127.0.0.1:5555`. PostgreSQL доступен только сервисам комплекса. Пароли пользователей хешируются Argon2id; браузерные сессии передаются в защищённых HttpOnly cookie.

### Передача звука

Браузер подключается к `/api/speech/session` по WebSocket и передаёт идентификатор назначенной попытки. Backend проверяет пользователя, состояние занятия и утверждение сценария.

Входящий звук передаётся бинарными сообщениями PCM16. Исходящий пакет содержит заголовок из трёх 32-битных чисел — поколение, порядковый номер и частоту дискретизации — и отсчёты Float32. Для исходящего звука используется частота 24 кГц. После воспроизведения браузер подтверждает номер пакета.

Микрофон остаётся активным во время ответа заявителя. При перебивании сервер отменяет устаревшие аудиопакеты. Очереди ограничены; переполнение приводит к явной ошибке. После обрыва соединения допускается подключение к сохранённому разговору в течение 30 секунд. Перенос живого разговора на другой речевой процесс не предусмотрен.
